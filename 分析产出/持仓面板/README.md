# 持仓面板 · 多账户 / 交易流水

单页应用 + 一个 SQLite 文件。**账户、买卖流水、分红、设置全部存在数据库里**，
程序本身没有外部依赖（SQLite 引擎已内联进 `index.html`，约 1 MB）。

## 文件

| 文件 | 作用 |
|---|---|
| `index.html` | 程序本体（含 SQLite WASM 引擎） |
| `config.js` | 目标权重与风控规则，由 `final_portfolio_v2.py` 生成，重跑会覆盖 |
| `holding.sqlite` | 你的数据库（首次打开时新建） |
| `portfolio.js` | 旧版持仓文件，只用于一次性导入 |
| `_selftest.js` | 逻辑自测，`node _selftest.js` |

**打开方式**：双击 `index.html`，首次会让你二选一：新建数据库 / 打开已有数据库。
选好后浏览器会记住这个文件，下次自动加载。浏览器安全策略要求每次重开页面确认一次权限，
顶部会出现提示条：

- **「授权并同步」** —— 本地没有未保存的改动，点它从磁盘读最新数据；
- **「授权写入」** —— 本地有改动还没写进文件，点它把改动写进 `.sqlite`。

## 数据到底存在哪（重要）

一份数据有三个位置，理解它们就不会「刷新后交易没了」：

| 位置 | 什么时候有 | 刷新会丢吗 |
|---|---|---|
| 内存 | 一直 | **会**，刷新即重建 |
| 浏览器缓存（IndexedDB） | 每次改动后自动写 | 不会 |
| `.sqlite` 文件 | 拿到文件授权后写 | 不会 |

所以**刷新不会丢数据**：改动先进浏览器缓存，下次打开页面从缓存恢复，再等你点「授权写入」落到文件里。
只有「换浏览器 / 清缓存 / 换电脑」时，还没落盘的那部分才会丢。顶部状态标签显示文件名的同时，
有未落盘改动时横幅会一直亮着提醒你点一下。

> 只在 Edge / Chrome 下验证过。其他浏览器不能直接写本地文件，数据会暂存在浏览器缓存里，
> 需要手动「另存为…」导出。

## 数据库结构

```sql
account(id, name, sort)                                   -- 账户
trade(id, acct, code, name, side, date, shares, price, fee, note)
dividend(id, acct, code, name, date, amount, tax, note)   -- 分红独立记账
setting(k, v)                                             -- 费用率、主题、当前账户
```

`trade.side` 是 `buy` / `sell`；`fee` 是佣金+印花税+过户费的合计，录入时自动算好。
可以直接用任何 SQLite 客户端（DB Browser for SQLite、`sqlite3` 命令行）打开查看或改数。

## 多账户

- 顶部下拉：**全部账户（合计）** 或某个具体账户
- 设置 → 账户：改名、新增、删除（删除会连它的流水一起删）
- 每个账户的持仓、成本、盈亏完全独立；「全部」视图按 `(账户, 代码)` 分别算成本，
  再按代码汇总市值与盈亏，不会把两个账户的成本混在一起

## 成本与盈亏口径

**移动加权平均，含交易费用。**

- **买入**：股数增加，总成本 `+= 成交额 + 费用`，成本价随之抬高
- **卖出**：股数减少，成本按卖出前的平均价结转（**成本价不变**），
  实现盈亏 `= 成交额 − 费用 − 结转成本`
- **分红**：独立累计，**不冲减成本价**。这是「分红单独算」的核心 ——
  否则分红会被伪装成成本下降，看不出真实收息
- **清仓**：股数归零后成本价归零，再买入重新起算；历史分红与已实现盈亏保留

页面上同时给四个口径，避免互相混淆：

| 指标 | 含义 |
|---|---|
| 持仓成本 | 当前持仓的总成本（含买入费用） |
| 浮动盈亏 | 市值 − 持仓成本（未实现） |
| 已实现盈亏 | 卖出结转的盈亏（已扣卖出费用） |
| 累计分红 | 到账分红（税前 / 扣税分开列） |
| 总盈亏 | 浮动 + 已实现 + 分红 |

## 交易费用

默认按你的实盘口径：

| 项目 | 默认值 | 收取方式 |
|---|---|---|
| 佣金 | 万分之 0.854 | 双边，**最低 5 元** |
| 印花税 | 0.05% | 仅卖出 |
| 过户费 | 0.001% | 双边 |

在「设置 → 交易费用」里可改。录入交易时费用框会自动填，也可以手动覆盖（覆盖后不再自动改）。
改费率只影响**以后**录入的费用，已存记录不动。

## 分红

分红是一张独立的表，字段是「税前金额 + 扣税」，到账 = 两者相减。

红利税按持有期限（财税 2015-101 号）：持股 1 个月内 20%、1 个月–1 年 10%、超过 1 年免税。
面板不自动判断持有期，由你填实际扣税金额。

分红不改变成本价，但会计入「总盈亏」和「累计分红」，所以除息日的账面浮亏不会让人误以为亏了。

## 其它

- **买入推荐 / 风险预警** 仍然读 `config.js` 的目标权重与 60 日均价，算法与旧版一致
- 行情来自腾讯 `qt.gtimg.cn`（失败自动退到东财 `push2`），每 10 秒刷新
- 「设置 → 导入 portfolio.js」把旧文件的持仓转成一笔笔买入，价格 = 原成本价、费用 = 0、日期 = 今天
- 整个 `holding.sqlite` 就是全部数据，拷走它即完成备份

## 已知限制

- 不记现金余额，所以「买入推荐」的本金取 `config.js` 的 `rules.capital`
- 卖出时按加权平均结转，不提供 FIFO 批次明细
- 份额/股数需手工录入，不自动同步券商
- 每次改动会把整个数据库重写一遍（几十 KB，无感知）

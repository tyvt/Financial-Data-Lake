# 打新底仓 · 最终筛选标准

> 本文档定义**当前生效**的选股标准条文（沪深统一框架），不记录某一次筛选的具体结果数值。
> 具体筛选结果、当前组合与权重见 [`当前打分与选股标准_2026-11-04.md`](当前打分与选股标准_2026-11-04.md) 与 `打新底仓_最终配置.md`。
> 最近一次校准：2026-11-05（基准日 2026-11-04）。

---

## 一、数据源与统一口径

### 1.1 数据源

| 用途 | 来源 | 备注 |
|---|---|---|
| 行情（收盘价、成交额、复权重建） | 数据湖 `daily_bars` | **自建前复权**，不依赖 qfq_close |
| 分红（每股派现、除权日） | 数据湖 `corporate_actions` | 逐次除权记录，**含中期分红** |
| 财报科目（净利、ROE、OCF、负债等） | 数据湖 `financial_statement_items` | 结构化科目，无财报原文 |
| 银行专项（核心一级、不良、拨备） | 数据湖 `bank_risk_metrics` | 东财 F10，取最新报告期 |
| 行业分类 | 数据湖 `industry_members`（`classification_system='sw'`） | **申万一级**，非人工打标 |
| 实控人性质（治理） | 交易所披露 / 东财 F10 → `实控人核查.csv` | 法人须证明国资，见 `国资主体白名单.csv` |

### 1.2 必须写死的口径

- **分红财年** = 除权日 − 8 个月的年份（含中期分红）。
- **股息率 TTM** = 近 12 个月已实施分红 ÷ 现价。
- **支付率** = 三年分红合计 ÷ 三年净利合计。
- **OCF/分红** = 三年经营现金流合计 ÷ 三年分红合计。
- **分红总额** = 每股派现 × 除权日当日股本（`share_structure` as-of 快照），不用最新股本。
- **年化波动 / 最大回撤**：252 个交易日重建前复权日收益，σ×√252、归一化净值最小回撤。
- **基准日** 由 `lake_base.pick_base()` 判定（全市场平均成交额 < 前 20 日中位数 80% 即判不完整，自动回退）。
- **数据充足性**：复权收益观测 ≥200 且行情天数 ≥252 才计算，否则不出数（停牌股不冒充）。

## 二、阶段一：市场准入（沪 11 条 / 深市专用 7 条）—— 沪深不强制统一

> **投资哲学：统一代码可以，标准绝不能统一。** 沪深能提供的标的类型不同，用同一把尺子量深市，只会把稳健的低波类债股（格力/兴蓉/粤高速）筛掉、翻出周期股与低基数反弹股。深市沿用经过无数踩雷（双汇治理、云南白药现金流、格力负债率微超）打磨出的「专用 7 条」防弹衣。

### 2.1 沪市 11 条（沪市基准）

**沪市 A 股 → 11 条同时满足。** 这是候选池，不是最终组合。

| # | 条件 | 阈值 | 计算 | 豁免 |
|---|---|---|---|---|
| ① | 连续三年分红 | d23/d24/d25 均 > 0 | 按财年归因每股派现（含中期） | 无 |
| ② | 三年平均股息率 | **> 3.5%** | 各年 dps ÷ 该年末收盘价，三年均值 | 无 |
| ③ | 连续三年净利同比为正 | 三年 `net_profit_yoy` 均 > 0 | 年报口径 | 无 |
| ④ | 资产负债率 | **< 60%** | 总负债 ÷ 总资产 | **银行豁免** |
| ⑤ | 支付率区间 | **30%–80%** | 三年支付率均值 | **公用事业豁免**（银行不豁免⑤，银行靠④豁免） |
| ⑥ | 经营现金流覆盖分红 | **> 1** | 三年 OCF ÷ 分红 均值 | 无 |
| ⑦ | ROE | **> 8%** | 三年 ROE 均值 | 无 |
| ⑧ | 现金流/净利 | **> 80%** | 三年 (经营现金流 ÷ 净利润) 均值 | 无 |
| ⑨ | 近 12 个月收益 | **> −20%** | 复权，252 交易日 | 无 |
| ⑩ | 三年净利 CAGR | **> 3%** | (np_now / np_base)^(1/3) − 1 | 无 |
| ⑪ | 三年累计分红 | **> 10 亿** | 三年分红总额合计 | 无 |

### 2.2 深市专用 7 条（深市防弹衣，不套沪市 11 条）

**深市 A 股 → 7 条同时满足。** 深市**主动豁免**沪市的成长/杠杆硬条件（净利逐年正增长③、ROE⑦、CAGR⑩、分红规模⑪、资产负债率④），改看「治理干净、波动低、分红稳、现金流覆盖得住」——因为底仓要的是市值稳定，不是成长。

| # | 条件 | 阈值 | 说明 |
|---|---|---|---|
| 1 | 基础池 | 深市 A 股，剔除 ST / 退市整理 | — |
| 2 | **治理底线** | 实控人为国资背景或无实际控制人 | 个人/家族/外资一票否决 |
| 3 | **低波底线** | 年化波动率 **< 25%** | 252 日重建复权；底仓第一职能是保市值 |
| 4 | **股息底线** | 当前股息率 **> 2.5%**，且近三年连续分红 | 2.5% 为深市现实让步；连续分红是硬要求 |
| 5 | **现金流底线** | 三年累计 OCF ÷ 三年累计分红 **> 1** | 分红必须由经营现金流挤出，不是借来的 |
| 6 | **支付率上限** | 三年**合计**支付率 **< 100%** | ≥100% 意味着分红超过当年利润，只能消耗存量现金 |
| 7 | 治理明确定性 | 治理须"明确通过"才计入入选 | 待确认/否决不计入 |

> **深市为何不套 11 条**：主池 11 条里股息率>3.5%、净利逐年正增长、CAGR>3% 等对深市是**结构性排斥**——深市低波标的（公用/交运/水务）往往利润微降但现金流覆盖分红，套 11 条会把这些真正的底仓标的筛掉，反而留下强周期股（如电投能源煤炭）与低基数反弹股（如东阿阿胶）。所以深市只看「治理 + 低波 + 股息 + 现金流 + 支付率」五件事。

### 2.3 两条豁免的理由（沪市）

- **④ 银行免资产负债率**：银行的负债是存款，是经营原料而非杠杆风险，用 60% 工商企业标准衡量银行没有意义。银行的风险改由第五节的核心一级资本充足率单独约束——**豁免一条，必须补一条更专业的**。
- **⑤ 公用事业免支付率区间**：水电热气属重资产、低增长、现金流稳定行业，70%–90% 支付率是常态。豁免后仍受 ⑥（OCF 覆盖分红 > 1）约束。

## 三、阶段二：打新底仓正交条件（沪市 ⑫⑬⑭ / 深市低波已含于专用7条）

11 条回答「是不是好股息股」，⑫⑬⑭ 回答「能不能当打新底仓市值」——两者正交，都要过。**深市专用 7 条已含低波<25% 与流动性门槛，不再单独套 ⑫⑬⑭。**

| # | 条件 | 沪市 | 深市 | 说明 |
|---|---|---|---|---|
| ⑫ | 年化波动率 | **< 25%** | 专用7条第 3 条已含 <25% | 底仓第一职能是保市值 |
| ⑬ | 63 日日均成交额 | **≥ 5000 万** | 专用7条已含流动性 | 真递补时能进能出 |
| ⑭ | 当前股息率 ÷ 三年均值 | **< 2 倍** | （深市不单独套） | 防"股价暴跌导致的假高股息" |

## 四、阶段四：银行专项（全市场统一，沪深所有银行同一门槛）

银行豁免了资产负债率（④ 及深市⑤），必须用行业专属指标替代。**不分市场**：

| 指标 | 门槛 | 字段 | 含义 |
|---|---|---|---|
| 核心一级资本充足率 | **≥ 9.5%** | `HXYJBCZL` | 硬门槛，不做例外 |
| 不良贷款率 | **≤ 1.5%** | `NONPERLOAN` | 资产质量底线 |
| 拨备覆盖率 | **≥ 180%** | `BLDKBBL` | 风险抵补厚度 |

> 实现见 `bank_screen.py`（`bank_gate`），沪深筛选主流程共用。核心一级不达标银行一律剔除、进观察池，**不单独降低门槛**。

## 五、阶段五：权重与沪深比例

### 5.1 市场内权重

```
score_i = 1 / sqrt(年化波动率_i × |最大回撤_i|)
w_i     = score_i / Σ score_j   （市场内归一化到 100%）
```

**为什么用几何平均**：波动率衡量日常抖动，最大回撤衡量极端损失。底仓怕"某天跌得很深"，不只是"每天抖得厉害"，两者相乘再开方等于在两种风险间取平衡。

### 5.2 沪深比例

- 执行比例 **沪 60% / 深 40%**（`w60` 档）。募资额参考比为 63/37（德勤 2026 前三季度 A 股沪深募资额），执行取 60/40 多留 3pct 给深市，避免逐季跟随波动。
- 弹性档：50/50、55/45、60/40（执行）、63/37。

### 5.3 集中度上限（硬约束，绝对权重）

| 约束 | 上限 | 处理 |
|---|---|---|
| 单一标的权重 | **≤ 25%** | 超出压至 25% |
| 单一行业权重（申万一级） | **≤ 35%** | 超出部分按 score 比例分给同市场未触顶标的，重查两级约束直至同时满足 |

行业一律按**申万一级**（`industry_members.industry_code` 前两位）判定，不按人工标签。行业上限优先于 score——它不允许"看起来分散、实际押注同一风险因子"。

## 六、入选标准 vs 卖出标准（两套阈值，不能合并）

**同一套阈值兼顾两件事，等于取消缓冲带。**

| 指标 | 入选线 | 卖出线 | 缓冲带作用 |
|---|---|---|---|
| 银行核心一级 | 9.5% | **9.0%** | 容纳 0.5pct 经营波动 |
| 公用 / 交运支付率 | 单年 < 80% | **连续两年 > 80%** | 容纳单年项目结算节奏 |
| 银行拨备 | ≥ 180% | **< 180% 且不良上升** | "与"非"或"，单点跌破只降权 |
| 年化波动率 | < 各自市场红线 | **> 各自市场红线** | 无缓冲，直接降权/移出 |

**完整卖出触发线、时间锚点、触发后处理见 `清单拉取与卖出触发_操作手册.md`。**

### 6.1 黑天鹅一票否决（定性，不看财务数据）

慢变量（支付率、资本充足、波动）恶化需 1–2 个报告期；合规与安全事故是快变量，财务没反映股价已崩。单列一条，不参与阈值判定。

| 触发事件 | 动作 |
|---|---|
| 实控人 / 董事长 / 财务总监被立案调查或采取强制措施 | **无条件清仓** |
| 审计报告被出具非标意见（保留 / 无法表示 / 否定） | **无条件清仓** |
| 重大安全、环保事故导致主营业务停摆 | **无条件清仓** |
| 财务造假被证监会立案，或被实施退市风险警示 | **无条件清仓** |

机制：`黑天鹅登记簿.csv` + 脚本强制触发，**登记即触发**，非自动巡检。**未登记 ≠ 无风险**；状态留空视为有效；解除需写明依据。配套季度人工巡检（审计意见、监管处罚、实控人变动、安环事故、重大诉讼）。

### 6.2 治理底线（结构化，可自动判定，全市场统一）

实控人字段来自交易所披露，结构化、可自动判定，因此放在**准入闸门**（11 条之外的一票否决）而非卖出线。**沪深同一标准、不区分市场。**

| 判定 | 结论 | 处理 |
|---|---|---|
| 中央/地方国有企业、无实际控制人 | 通过 | 正常纳入 |
| 个人或家族（自然人） | **否决** | 不得入选；已持仓 → 清仓换仓 |
| 民营（非国资法人） | **否决** | 同上 |
| 外资企业 | **否决** | 同上 |
| 字段缺失 / 抓取失败 | **缺失** | 不通过，计入 `实控人核查_异常.csv` |

> 判定规则：实控人若为法人，必须能证明是国资（命中国资委/政府/财政关键词，或在 `国资主体白名单.csv`）；两都不满足按"未能证明国资"否决。名录每加一条须写依据。

## 七、已知数据缺陷与局限（2026-11-05 复核）

1. **无财报原文**，仅结构化科目——无法识别会计政策变更、非经常损益占比。底仓靠分红与波动，可接受，不影响筛选。
2. **筛选器不知道估值**——通过标准只说明分红/现金流/波动达标，不说明当前价贵不贵。
3. **历史不预测未来**——三年均值是后视镜。
4. **分红与银行指标为东财单一来源**，未做第二源交叉；抓取失败标 SKIP 计入数据完整性，**不静默通过**（缺数据 ≠ 达标）。
5. **黑天鹅靠人工登记**——脚本不读公告/新闻，登记簿空着只代表没人填（见 6.1）。
6. **治理判定靠名录维护**——「是不是国资」非结构化，靠 `国资主体白名单.csv` / `非国资法人名单.csv` 认，两者都没覆盖的进「待确认」，不当国资放行也不当民营否决。

> 已闭环项：分红改读湖内 `corporate_actions`（含中期分红）；行业改申万一级；复权自建（湖内 `daily_bars` 无 qfq_close，本就不依赖）。详见 `数据来源清单.md` F 节。

### 8.3 标准变更流程

1. 改本文档对应章节，写明变更理由和影响范围；
2. 改 `screen_sh.py`（沪市）/ `screen_sz.py`（深市）/ `bank_screen.py` 的阈值常量（阈值集中，不散落正文）；
3. 跑 `tests_qa_negative.py`，确认新阈值上下沿有测试覆盖；
4. 跑 `screen_sh.py` + `screen_sz.py` → `reselect_portfolio.py` → `final_portfolio_v3.py`，19 项校验通过后重出报表。

**顺序不能反。** 先改脚本再补文档，迟早出现"脚本查 A、文档写 B"——这类不一致不会报错，只会让下一个人按错的规则做决定。

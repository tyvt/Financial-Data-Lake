## 一、DL-2026-1018-01（`qfq_close` 失效）——已修复

### 1.1 最小复现用例

```sql
SELECT trade_date, close, qfq_close, hfq_close, adj_is_exact
FROM daily_bars_adj WHERE symbol='601288.SH'
  AND trade_date BETWEEN DATE '2026-05-11' AND DATE '2026-05-15' ORDER BY 1;
```

| trade_date | close | qfq_close | 复权日收益 | adj_is_exact |
|---|---|---|---|---|
| 2026-05-11 | 6.81 | 6.6794 | — | true |
| 2026-05-12 | 6.78 | 6.6500 | −0.44% | true |
| 2026-05-13 | 6.66 | 6.6600 | **+0.15%** | true |
| 2026-05-14 | 6.76 | 6.7600 | +1.50% | true |
| 2026-05-15 | 6.67 | 6.6700 | −1.33% | true |

工单记录的是 05-12→05-13 表观 −1.77%（分红缺口未抹除）；现在为 **+0.15%**，与工单 §5.3 第 5 条「应为 ≈ −0.15% 量级」一致（方向差异来自当日真实涨跌，量级吻合）。缺口已消除。

### 1.2 逐条验收

| 工单验收标准 | 实测 | 判定 |
|---|---|---|
| ① 恒等：最新交易日 `qfq_close = close`，误差 < 0.01 元 | 5,825 只**全部**满足，最大偏差 **0.0000** | ✅ |
| ② 除权日检验：50 个事件的复权收益偏离 < 0.5 pct | 全量 4,158 个除权日：\ | r \| 中位数 **2.44% → 1.71%**，均值 4.85% → 2.42% | ✅ |
| ③ 连续性：`\|r_adj\| > 7%` 且无除权记录 < 0.1% | 实测 **5.30%** | ⚠️ 标准标定有误，见 1.4 |
| ④ 覆盖率：`adj_is_exact=false` < 5% | **0.02%**（原 60.9%） | ✅ |
| ⑤ 回归：农行 2026-05-13 收益 ≈ −0.15% 量级 | **+0.15%** | ✅ |

### 1.3 全历史覆盖

| 年份 | 行数 | `adj_is_exact=false` | `qfq_close = close` 占比 |
|---|---|---|---|
| 2016 | 642,210 | 0.00% | 7.59% |
| 2018 | 817,583 | 0.00% | 11.53% |
| 2020 | 946,207 | 0.005% | 16.91% |
| 2022 | 1,146,506 | 0.021% | 18.64% |
| 2024 | 1,233,444 | 0.020% | 23.60% |
| 2025 | 1,248,136 | 0.019% | 29.73% |
| 2026 | 976,464 | 0.019% | 58.10% |

`qfq = close` 的占比从 2016 年 7.6% 单调升到 2026 年 58.1%，方向正确：距今越近，累计分红越少，前复权调整幅度越小；最新一日必然 100% 相等。若仍是"未生效"，该列会全历史恒为 100%——所以现在的形态是修复生效的证据，不是缺陷。

### 1.4 关于验收标准 ③ 不达标

`|r_adj| > 7%` 且无除权记录占比 5.30%，远高于工单要求的 0.1%。但这不是缺陷回归：

- 同一口径下**未复权** `close` 为 5.32%，复权后 5.30%，两者几乎无差别——说明 7% 以上的跳变不是除权造成的；
- 除权日与非除权日的收益分布已经不可区分（中位数 1.705% vs 1.670%，>3% 占比 27.44% vs 26.62%，>7% 占比 5.80% vs 5.32%）；
- 该数据集正常交易日本身就有约 5% 的样本超过 7%（涨跌停、新股、ST 异动）。

结论：标准 ③ 的阈值没有先在本底分布上校准，直接按 0.1% 卡会造成永久性误报。建议改为**除权日与非除权日分布对照**（当前已通过），或把阈值提到 ≥10%。

### 1.5 遗留项（不影响结论）

1. **视图仍用精确 join 而非 ASOF**：`daily_bars_adj` 定义里是 `b.trade_date = h.trade_date`，因子缺行时 `COALESCE(factor, 1.0)` 静默回退。当前缺失率 0.02%，但机制上没改——一旦因子派生中断一天，那一天会静默退化为不复权，且只有 `adj_is_exact` 一个弱信号。工单 §4 第 2 条推测的这个根因仍然存在。
2. **`adj_is_exact` 告警已实现**：`query/reader.py` 与 `mcp_server/tools.py` 在命中 false 时会打 warning（"Treat those prices as unadjusted"），`quality/cross_checks.py` 也有对应检查项。工单 §7 的 P1 这条算完成。
3. **P2 的 `qfq_returns` 派生视图未提供**：下游仍需自行实现日收益计算，口径分裂的成本依然在。

## 二、DL-2026-1019-01（盘中/残缺快照交易日）——未修复

### 2.1 现象仍在

2026-10-16 仍是 `max(trade_date)`，且仍是残缺日：

| 指标 | 2026-10-15 | 2026-10-16 | 比值 |
|---|---|---|---|
| 全市场个股平均成交额 | 31,307.0 万 | **13,438.2 万** | 42.9% |
| 前 20 日中位数 | 32,219.8 万 | — | 41.7% |
| 粤高速A `000429.SZ` 成交量 | 13,872,600 | **36,300** | 0.26% |
| 粤高速A 收盘价 | 13.58 | **14.55** | +7.14% |

与工单记录的数值完全一致，一点没动。

### 2.2 根因：不是"盘中抓取"，是**兜底源写入了空快照**

工单推测"抓取任务在收盘前执行"。按 `fetched_at` 拆开看，这个判断不成立——那批数据是 **2026-10-17 10:27**（盘后）写入的。真正的问题在**来源降级**：

| 来源 | 标的数 | 平均成交额 | 成交额 < 自身 20 日中位数 10% 的只数 |
|---|---|---|---|
| `exchange`（交易所） | 2,316 | 31,621.3 万 | 0 / 2,316（0.0%） |
| `bse`（北交所） | 350 | 3,934.9 万 | 0 / 350（0.0%） |
| `tdx_protocol_quote`（通达信实时报价兜底） | 2,900 | **66.7 万** | **2,878 / 2,900（99.2%）** |
| `tdx_protocol` | 1 | 14,214.2 万 | 0 / 1 |

交易所直连的 2,316 只完全正常；**坏的是降级到实时报价源的 2,900 只，其中 99.2% 成交额接近归零**。`000429.SZ` 的 `source` 正是 `tdx_protocol_quote`。

所以缺陷链是：**主源部分失败 → 降级到实时报价兜底 → 兜底源在非交易时段返回空/近零快照 → 无任何校验 → 落库**。工单建议的"增加收盘后时间校验"挡不住这个——数据本来就是盘后写的。"提升时间段校验"这条修不了问题。

### 2.3 为什么能落库：失败了仍然发布

当天 `daily:core` 的运行记录：

```
status=failed  execution_status=failed  coverage_status=partial  publication_status=published
error_message='one or more core steps failed'
```

**步骤判定失败，但 `publication_status` 仍是 `published`**。这是缺陷能进入正式分区的直接原因。修这一条（failed 时阻断发布，或至少标记 `data_version`）比加工时间校验有效得多。

### 2.4 污染范围：近 5 个月唯一一天

按标的做异常检测（单只成交额 < 自身 20 日中位数 10%）：

| trade_date | 标的数 | 异常占比 |
|---|---|---|
| 2026-10-16 | 5,217 | **55.17%** |
| 其余所有交易日（2026-06-01 起） | — | **全部 < 1%** |

这个判据区分度极高（55% vs <1%），且只锁定一天。工单 §6 提到的"按标的做成交量异常检测"其实是比全市场判据更可靠的方向——见 3.2。

### 2.5 工单建议的两条入库侧措施：均未实现

| 建议 | 现状 |
|---|---|
| ① 入库侧收盘后校验 / 成交额低于 20 日中位数 80% 不写库 | 未实现。`cne verify` 只查新鲜度与空表，跑出来 3 个缺口（`hot_rank`、`sector_fund_flow` 空表 + `industry_index` 陈旧），**完全没报 10-16** |
| ② 增加 `is_complete` / `snapshot_at` 字段 | 未实现。`daily_bars` 现有字段：`symbol, trade_date, open, high, low, close, pre_close, volume, amount, source, data_version, fetched_at`。没有完整性标记，"数据是否收全"仍不可查询 |

## 三、工单之外的新发现

### 3.1 数据已停更，缺 2026-10-19

`daily_bars` 最大日期 2026-10-16，但 10-19（周一）是交易日。运行记录显示：

| 时间 | job | 结果 |
|---|---|---|
| 2026-10-16 14:07（修订：UTC 06:07） | `daily:core` | failed / published（即 10-16 那次） |
| 2026-10-17 10:06 | `daily:*` 全组 | `skipped_non_trading_day`（周六，正常） |
| 2026-10-19 | — | **无任何 daily 运行记录** |
| 2026-10-20 上午 | — | 无记录（今日未收盘，不算缺） |

其他数据集同步停在 10-16：`index_bars`、`fund_flow`、`valuation_metrics`、`market_breadth`、`sector_bars`、`adj_factors` 全部 10-16；`margin_trading` 10-15。

所以现在的状态不是"最后一天脏"，而是**缺了 1 个完整交易日（10-19）**，且 10-16 那天的 2,900 只仍是脏的。

### 3.2 全市场 80% 判据会大量误伤正常日

如果下游 `lake_base.pick_base()` 真按"全市场平均成交额 < 前 20 日中位数 80% 即回退"，2026 年内会命中 20+ 个**正常**交易日：

| trade_date | 占比 | trade_date | 占比 |
|---|---|---|---|
| 2026-09-30 | 78.4% | 2026-07-24 | 67.3% |
| 2026-08-26 | 77.4% | 2026-07-16 | 73.1% |
| 2026-08-03 | 77.5% | 2026-04-07 | 75.3% |
| 2026-07-28 | 75.0% | 2026-02-11 | 72.3% |

这些是真实缩量（且多为连续 2–3 天，符合市场节奏），不是快照截断。80% 阈值会把它们全判成"不完整"并回退一个交易日，导致基准日在缩量行情里系统性错位。

建议改为**按标的判据**：某只标的 `amount < 自身 20 日中位数 × 10%` 且 `|涨跌幅| > 3%` 即异常，异常标的占比 > 20% 判该日不完整。本轮实测该判据只有 10-16 触发（55.17%），其余全部 <1%，无误伤。

## 附：复核用查询

```sql
-- 1019-01 现象复现
select trade_date, count(*) n, round(avg(amount)/1e4,1) avg_amount_wan
from daily_bars where trade_date >= DATE '2026-10-08' group by 1 order by 1;

-- 1019-01 按来源定位坏数据
select source, count(*) n, round(avg(amount)/1e4,1) avg_amt_wan
from daily_bars where trade_date = DATE '2026-10-16' group by 1 order by 2 desc;

-- 1019-01 按标的异常检测（比全市场判据可靠）
with b as (
  select symbol, trade_date, amount,
    median(amount) over (partition by symbol order by trade_date
      rows between 20 preceding and 1 preceding) med
  from daily_bars where trade_date >= DATE '2026-06-01'
)
select trade_date, count(*) n,
  round(100.0*sum(case when amount < 0.1*med then 1 else 0 end)/count(*),2) lt10_pct
from b where med is not null group by 1 having lt10_pct > 1 order by 2 desc;

-- 1018-01 恒等检验
with last as (select symbol, max(trade_date) d from daily_bars_adj group by 1)
select count(*) n, sum(case when abs(qfq_close-close) < 0.01 then 1 else 0 end) ok
from daily_bars_adj a join last l on a.symbol=l.symbol and a.trade_date=l.d;

-- 1018-01 除权日分布对照
with r as (
  select symbol, trade_date,
    close/lag(close) over w - 1 as ret_raw,
    qfq_close/lag(qfq_close) over w - 1 as ret_adj
  from daily_bars_adj where trade_date >= DATE '2026-01-01'
  window w as (partition by symbol order by trade_date)
),
ca as (select distinct symbol, cast(ex_date as date) ex_date from corporate_actions)
select (ca.symbol is not null) is_ex, count(*) n,
  round(median(abs(ret_raw))*100,2) med_raw,
  round(median(abs(ret_adj))*100,2) med_adj
from r left join ca on r.symbol=ca.symbol and r.trade_date=ca.ex_date
where ret_raw is not null group by 1;
```

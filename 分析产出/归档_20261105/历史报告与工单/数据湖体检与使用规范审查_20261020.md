## 二、新发现的数据问题

### A1 `pre_close` 字段实质为空（99.98%）

| 年份 | 行数 | `pre_close` 为 null 占比 |
|---|---|---|
| 2021–2025 | 各 106–125 万 | **100.00%** |
| 2026 | 982,027 | 99.73% |

全表仅 2,670 行有值。**影响**：任何用 `pre_close` 校验涨跌幅、计算「一字板」、判断跳空的分析都是空转——上一轮体检里我那条「`pre_close` 与昨收偏离」的检查就是被这个字段骗成 0 违规。
**绕过方式**：用 `lag(close)` 自算昨收，`daily_bars_adj` 的收益列也可以。
**建议**：要么补数据，要么从 schema 里移除（留一个看似可用、实则全空的字段，比没有更危险）。

### A2 26 次复权因子跳变，公司行为表里没有对应记录

`hfq_close/close` 比值应在除权日跳变、其余日恒定。2025 年以来共 8,893 次跳变，其中 **26 次在任何 `corporate_actions` 记录里都找不到对应除权日**，幅度最大 **1.461x**：

| 标的 | 跳变日 | 比值 | 当日表观涨跌 |
|---|---|---|---|
| 000908.SZ 石药景峰 | 2026-03-11 | 1.461 | −28.1%（6.37→4.58） |
| 600165.SH 宁科生物 | 2025-12-11 | 1.423 | — |
| 002713.SZ 东易日盛 | 2025-12-30 | 1.351 | — |
| 300506.SZ 名家汇 | 2025-12-22 | 1.326 | — |

**性质**：湖的复权因子认了「这天有权益重置」，但 `corporate_actions` 没有这条记录——**两个数据集对同一件事给出相反答案**。26 次中 15 次伴随 >5% 跳空，形态集中在大股东重整/出资人权益调整类标的（ST 为主）。

**影响**：
- 用湖 `qfq_close` 的人：得到正确的复权序列，但不知道有这件事；
- 按 `corporate_actions` 自建复权的人（我们）：把 −28% 当成真实暴跌，**波动率虚高、回撤虚深**。

方向是保守的（虚高→被 25% 波动线筛掉，不会误纳），但对全市场扫描是系统性误杀。**当前 26 只全部是 ST/问题股，不在 8 只持仓，也不在 26 只深市合格池里**。

**建议**：让 `corporate_actions` 补这 26 条（或加一个 `non_cash_event` 类型），否则两套复权路径永远对不上。

### A3 财报的 PIT 字段实质不可用 + 2,136 行重复

| 检查 | 结果 |
|---|---|
| `available_at` 为空 | **2,793,903 / 2,793,903（100%）** |
| `observed_at` 为空 | 0 |
| 重复键 `(symbol, report_period, item_code)` | **2,136 行**（同值、`revision_id` 不同） |

`financial_statement_items` 的契约写着 `pit=True`、`pit_grade=partial`、`availability_col=announce_date`、`watermark=False`。但 `available_at` 全空，意味着**无法按「当时能看到什么」回放**——做历史时点选股会引入前视偏差。重复行虽同值，直接 join 会放大 2,136 行（我们的用法是 `max(case when...)` 聚合，不受影响，但这是个地雷）。

**建议**：`available_at` 用 `announce_date` 回填；重复行按 `revision_id` 保留最新一条。

### A7 我们自己的 bug：除权日停牌会丢掉分红（已修）

不是湖的问题，是 `screen_sz.rebuilt_returns` 的问题，但由这次体检发现：

- **机理**：原实现要求 `ex_date` 与行情日期**精确同日**才套用分红。除权日停牌时当天没有 K 线，`reindex` 直接把这条分红丢了。
- **实证**：600717 天津港 2026-06-18 除权（每股 0.102 元），06-08 起停牌、06-23 复牌。复牌日实际 +3.85%（4.37 / (4.31−0.102) − 1），我们的旧代码算出 **+1.39%**（4.37/4.31−1）——差额 2.46pct 正是分红被当成了下跌。
- **反向情形也错**：若矩阵里有别的标的当天在交易，该行虽不丢，却落在停牌日上，制造一个假的 −2.37% 加一个假的 +3.85%，波动率被抬高。
- **修复**：把除权日映射到「该股实际有成交的第一天」。修复后 600717 与湖 `qfq_close` 逐日一致（差 4.7e-10）。
- **影响面**：2025 年以来 A 股共 **14 例**除权日停牌；8 只持仓与 26 只深市合格池**零影响**（10-15 基准重跑，代码集与全部指标逐位相同）。
- **同一 bug 也存在于 `annual_review.py`**（`年度复核_指标明细.csv` 的来源，直接决定组合的波动率与股息率），已按同一方式修复。8 只持仓在 10-15 基准下的指标修复前后完全不变（22.18% / 23.50% 等逐位相同），因为它们的除权日都在交易日内。
- **已加测试**：`tests_qa_negative.py` 新增 N1–N3（含证伪对照），总计 **140/140 通过**；报表校验 23/23 通过（项数以 `校验结果.txt` / `校验器自测结果.txt` 的落盘结果为准，不放这两个文件之外的数字）。

## 三、使用方式审查：符合规范吗？

### 3.1 湖的分层与契约（先对齐概念）

`cnequity.domain.datasets` 注册了 55 个 `DatasetSpec`，关键字段：

| 字段 | 含义 | 对我们的约束 |
|---|---|---|
| `layer` | `curated`（源数据）/ `derived`（湖内计算） | 我们的产物应是 derived 或分析层，不该进 curated |
| `tier` | L0–L8 依赖层级 | 决定更新顺序 |
| `pit` / `pit_grade` | 是否支持时点回放 | 决定了能不能做历史选股 |
| `unit_contract` | 单位合同，如 `volume: share`、`amount: CNY` | 换算错误会被它抓住 |
| `primary_source` / `supplementary_sources` | 主源 + 辅源 | **我们绕过它自己抓 = 重复建设** |

实测的几个关键契约：

```
daily_bars     curated L1  pit=none     主源 tdx_protocol   单位 {price:CNY/share, volume:share, amount:CNY}
corporate_actions curated L2 pit=none   主源 eastmoney（辅 baostock,ths）  单位 cash_dividend: CNY/share
financial_statement_items curated L3 pit=partial(announce_date) 主源 eastmoney
industry_members curated L5 pit=none    主源 eastmoney
```

### 3.2 逐项对照

| 需求 | 湖里有没有 | 我们现在的做法 | 判定 |
|---|---|---|---|
| 复权收益 | **有** `daily_bars_adj.qfq_close`（已验证与自建一致） | 自建 30 行复权 | ⚠️ 重复，但自建可作交叉校验 |
| **分红明细** | **有** `corporate_actions`，2025 至今 **4,309 只 / 10,087 条**，含中期分红 | 从东财抓 `RPT_SHAREBONUS_DET`(逐只) + AKShare `stock_fhps_em`(整批) | ❌ **重复且更差** |
| **行业分类** | **有** `industry_members` 两套（申万 5,934 只 @10-16、东财 5,577 只 @10-19） | 人工打 8 个汉字标签 | ❌ **重复且更差** |
| 净利 / 经营现金流 | 有 `financial_statement_items` | 用湖 | ✅ 符合 |
| 股票池 / ST 过滤 | 有 `instruments` + `trading_status.risk_warning` | 用湖（`name not like '%ST%'` 字符串匹配） | ⚠️ 应用 `risk_warning` 字段而非名称匹配 |
| 实际控制人 | **没有**（`top_holders` 只有前十大股东 + `holder_type`，无「实际控制人」） | 东财 F10 抓取 + 本地 CSV | ✅ 必要补充，但应回写进湖 |

### 3.3 最重要的一处：分红，湖里本来就比我们全

我们为了「深市全市场分红」从东财抓了两个接口，而 `corporate_actions` 里已经有：

| 标的 | 湖内记录（ex_date / 每股） | 我们的口径 |
|---|---|---|
| 云南白药 | 2025-04-30 **1.185** / 2025-09-24 **1.019** / 2026-04-30 **1.583** / 2026-09-24 **1.038** | 只用 1.583（财年方案），**漏了中期 1.038** |
| 格力电器 | 2025-05-15 1.0 / 2025-08-29 2.0 / 2026-01-23 1.0 / 2026-08-27 2.0 | 只取年度方案 |
| 粤高速A | 2025-07-14 0.523 / 2026-08-10 0.604 | 与湖一致 ✅ |

**结论**：`corporate_actions.primary_source = eastmoney`，我们抓的也是东财——等于把同一份数据经二手转发一遍，还因为抓的是「年度方案」接口而丢掉了中期分红。深市扫描器漏 852 只中期分红那个「已知局限」，**根因不是湖不行，是我们没用湖**。

**改法**：`screen_sz.fetch_dividend()` 改为读 `corporate_actions`，按 `ex_date` 聚合；财年口径 = 按 `ex_date` 落在该财年内的记录求和，TTM 口径 = 按 `ex_date` 滚动 12 个月求和。两个口径都能算，且不依赖外网。

### 3.4 口径风险：行业上限的粒度没定义，它直接决定粤高速的权重

湖里两套分类对同一批标的给出不同粒度：

| 标的 | 东财 `industry_name` | 申万三级 `industry_code` |
|---|---|---|
| 601000 唐山港 | 交通运输 | 421102（港口） |
| 601298 青岛港 | 交通运输 | 421102（港口） |
| 000429 粤高速A | 交通运输 | 420901（高速公路） |

- **按东财 / 申万一级 42（139 只）**：三者同属交运 → 合计 35.00%，**粤高速只能拿 9.52%**（即上一轮的执行结果）；
- **按申万二级 4211 航运港口（36 只）/ 4209 公路铁路（33 只）**：港口 25.48%、高速 9.52%，**两个都不触 35%**，粤高速本可按 score 拿 **11.73%**；
- **按申万三级**：港口 17 只、高速 20 只，结论同上。

也就是说，**上一轮把粤高速从 11.73% 压到 9.52%，成立的前提是「行业 = 一级」这个未言明的选择**。这不是算错，是规则没写清粒度。参考：现在用的是东财分类，东财「交通运输」等价于一级，所以执行结果自洽；但如果哪天换成申万三级，同一套规则会给出不同答案。

**必须补一条定义**：行业上限按哪个层级判？建议按**申万一级**（口径最粗、最难被结构设计绕过），并写进标准文档；同时把人工 `ind` 列替换为 `industry_members` 的申万一级映射，消除 8 个人工标签这个单点。

### 3.5 该进湖 / 不该进湖

| 内容 | 位置 | 理由 |
|---|---|---|
| 分红明细（已有） | 湖 curated | 直接用，不必重抓 |
| 行业分类（已有） | 湖 curated | 直接用，替换人工标签 |
| **实控人性质**（缺） | **应进湖**（derived 或 curated 新数据集） | 它是外部抓取的事实字段、有明确来源和抓取时间，符合 curated 的定义；现在散落成本地 CSV，换机器就丢，且无法复现抓取时点 |
| `pre_close` | 湖（待补或待删） | 字段存在但无数据，比缺字段更危险 |
| 国资白名单 / 非国资法人名单 | **不进湖** | 人工判断 + 依据，属于研究结论 |
| 黑天鹅登记簿 | **不进湖** | 人工登记，且湖内源只覆盖近 10 天 |
| 替补席 / 换仓执行记录 | **不进湖** | 决策记录，不是市场数据 |
| 组合与权重 | **不进湖** | 同上 |

判据一句话：**能被外部源复现的事实进湖，依赖人工判断的结论留分析层。**

## 五、复现

```bash
cd D:/repository/数据湖
python 分析产出/audit_lake.py         # 15 项体检
python 分析产出/tests_qa_negative.py  # 140 项校验器自测
```

体检脚本只读（`read_only=True`），不写湖、不动任何产物。

**一个操作提醒**：湖已经到 2026-10-19，而组合是 2026-10-15 基准执行并发布的。`screen_sz.py` / `annual_review.py` 默认取湖内最新交易日，直接裸跑会把产物悄悄滚到 10-19——本次两个脚本都显式加了 `--base 2026-10-15` 才保证与已发布内容一致。滚动本身没有错（10-19 是修复后的干净数据），但它会同时改动 26 只池、11 只波动率、全部股息率，**应当作为一次独立的「换基准」动作来做，而不是体检的副产品**。

滚动到 10-19 的实际影响（已试算后回退）：26 只池 → **27 只**（新增山西证券 002500.SZ），11 只波动率变化 ≤0.45pct、股息率普遍下降 0.1–0.2pct（粤高速 23.50→23.44、4.45→4.34；云南白药 13.78→13.86、2.99→2.92）。没有任何一只跨越 25% 波动线或 2.5% 股息线。
